Two entry points compute the same function of the same buffer: the descending run/tot recurrence over each window's buckets, plus one closing add. repro_direct spells it the obvious way, three inlined pt_add_g2 call sites; repro_folded routes every operation through a single call site. A correct compiler makes the outputs byte-identical, and desktop Chrome does. Safari on an iPhone 15 Pro (iOS 18.7, Safari 26.6) returns all-identity points from the three-site spelling, and at four or more sites returns garbage that differs on every run; running the three-site kernel has also been seen to lose the device outright. No barrier, no workgroup storage, no atomics, one thread per workgroup: nothing here is allowed to race. Needs g2.wgsl beside it: cargo run -p g16-wgpu --example dump_points_wgsl g2 > web/static/dbg/g2.wgsl.
