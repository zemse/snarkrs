# Required test resources

`resources.rs` is shared test-only source, included by formats and groth16 tests.
It adds no production API or dependency.

Set `G16_REQUIRE_TESTS=1` when a selected test must exercise its resource-backed
coverage. A missing resource panics with the test context and missing path or
setup requirement. Unset, `0`, and every value other than exactly `1` allow
explicit `SKIPPED` messages. Use `--nocapture` to see those messages on passing tests.

The existing oracle contract remains: any set `G16_REQUIRE_VECTORS`, including
an empty value or `0`, requires vectors. It does not require non-vector resources.
Neither variable causes ignored tests to run.

## Implemented coverage

- formats: artifact-backed unit tests, missing reference proofs, and snarkjs exports.
  Export tests require snarkjs 0.7.6 (`SNARKJS` may name its executable or `cli.js`).
  Both `tiny_mul` and `js_1x1_d8` must have the files used by the selected export test.
- groth16: CPU circuit fixture tests, artifact-backed CPU prover tests, missing
  reference proofs, the shifted-L fixture, and H, MSM, and FFT oracle tests.
  H and MSM require their expected JSON, key, and witness in each artifact directory;
  the strict mode rejects incomplete directories rather than filtering them silently.
  FFT requires `bench/fft-vectors/fft_{13,14,16}.json`.

Fixtures live under `bench/artifacts`; see `bench/scripts/gen-artifacts.sh` for their
setup. The general formats/prover artifact suites require `circuit.zkey`,
`circuit.wtns`, `vkey.json`, and `public.json`. Reference-proof tests also require
`proof.json`. No fixtures are generated by these guards.

Ceremony, CLI, witness, Metal, wgpu, CUDA, and other crates are **not covered yet**.
This is a partial implementation of REV-25, not a workspace-wide strict mode.

## Bounded regression checks

From the repository root:

```sh
cargo fmt --all
cargo check --locked -p snarkrs-formats -p snarkrs-groth16 --tests
python3 test-support/test_resources.py -v
```

The Python tests use only the standard library. They compile the real helper with
`rustc`, exercise synthetic absent/incomplete/complete files and vector/device
reasons in isolated child environments, and run only the formats
`zkey_export_json_matches_snarkjs` entrypoint with a nonexistent `SNARKJS` path.
No actual fixture is removed, no oracle computation or proof is run, and no device
is claimed tested. The device probe checks the helper only, not a backend branch.
