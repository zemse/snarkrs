# Required test resources

`resources.rs` is shared test-only source, included by formats and groth16 tests.
It adds no production API or dependency.

Set `G16_REQUIRE_TESTS=1` when a selected test must exercise its resource-backed
coverage. A missing resource panics with the test context and missing path or
setup requirement. Unset, `0`, and every value other than exactly `1` allow
explicit `SKIPPED` messages. Use `--nocapture` to see those messages on passing tests.

The existing oracle contract remains: any set `G16_REQUIRE_VECTORS`, including
an empty value or `0`, requires vectors. It does not require non-vector resources.
Neither variable causes ignored tests to run.

## Implemented coverage

- formats: artifact-backed unit tests, missing reference proofs, and snarkjs exports.
  Export tests require snarkjs 0.7.6 (`SNARKJS` may name its executable or `cli.js`).
  Both `tiny_mul` and `js_1x1_d8` must have the files used by the selected export test.
- groth16: CPU circuit fixture tests, artifact-backed CPU prover tests, missing
  reference proofs, the shifted-L fixture, and H, MSM, and FFT oracle tests.
  H and MSM require their expected JSON, key, and witness in each artifact directory;
  the strict mode rejects incomplete directories rather than filtering them silently.
  FFT requires `bench/fft-vectors/fft_{13,14,16}.json`.

Fixtures live under `bench/artifacts`; see `bench/scripts/gen-artifacts.sh` for their
setup. The general formats/prover artifact suites require `circuit.zkey`,
`circuit.wtns`, `vkey.json`, and `public.json`. Reference-proof tests also require
`proof.json`. No fixtures are generated by these guards.

Ceremony, witness, and other crates are **not covered yet** by `resources.rs`.
CLI required conformance is a separate opt-in gate below. Existing backend-specific
and optional local suites remain unchanged. This is not a workspace-wide strict mode.

## Bounded regression checks

From the repository root:

```sh
cargo fmt --all
cargo check --locked -p snarkrs-formats -p snarkrs-groth16 --tests
python3 test-support/test_resources.py -v
```

The Python tests use only the standard library. They compile the real helper with
`rustc`, exercise synthetic absent/incomplete/complete files and vector/device
reasons in isolated child environments, and run only the formats
`zkey_export_json_matches_snarkjs` entrypoint with a nonexistent `SNARKJS` path.
No actual fixture is removed, no oracle computation or proof is run, and no device
is claimed tested. The device probe checks the helper only, not a backend branch.

## Required CLI conformance (Stage4 PAR-F)

`conformance.rs` is small test-only source shared by the CLI integration targets.
Its selection and fixture-list guards do not allocate. It adds no dependencies.
Guard unit tests run without artifacts or devices; proof gates are ignored until
explicitly selected. An ignored gate is not proof evidence.

Prerequisites:

- Existing `tiny_mul` and `sha256` artifacts, each with `circuit.zkey`,
  `circuit.wtns`, `vkey.json`, and reference `public.json`.
- `tiny_mul` also needs `proof.json`, `h_expected.json`, and `msm_expected.json`.
- Executable snarkjs on PATH, or `SNARKJS=/absolute/path/to/snarkjs` (an executable,
  not a JS module). Before preparing any key/device, it must successfully verify
  the tiny reference proof and print `OK!`.
- One explicit backend, work mode, and profile per process. No default selection,
  comma-separated backends, unknown values, duplicates, or missing cases. These
  conditions fail nonzero with `UNAVAILABLE`, never pass or silently skip.
- `G16_CONFORMANCE_ROOT` can point to an existing absolute artifact root outside
  a worktree. No test generates fixtures or installs tools.

From the repository root, CPU guards/build and both required CPU modes:

```sh
cargo test --release --locked --offline -j 2 -p snarkrs-cli --no-default-features --features cpu --test conformance --test large
cargo build --release --locked --offline -j 2 -p snarkrs-cli --no-default-features --features cpu --bin snarkrs
export G16_CONFORMANCE_ROOT=/absolute/path/to/bench/artifacts
export G16_CONFORMANCE_FIXTURES=tiny_mul,sha256
G16_CONFORMANCE_BACKEND=cpu G16_CONFORMANCE_WORK=variable G16_CONFORMANCE_PROFILE=none cargo test --release --locked --offline -j 2 -p snarkrs-cli --no-default-features --features cpu --test conformance required_backend_conformance -- --ignored --exact --nocapture --test-threads=1
G16_CONFORMANCE_BACKEND=cpu G16_CONFORMANCE_WORK=constant G16_CONFORMANCE_PROFILE=none cargo test --release --locked --offline -j 2 -p snarkrs-cli --no-default-features --features cpu --test conformance required_backend_conformance -- --ignored --exact --nocapture --test-threads=1
```

The gate uses library APIs, with no fallback. It compares H and all five MSMs
against CPU, resident H against host H, pinned proofs at zero/nonzero blinders,
repeat proofs on a prepared circuit, and reference public signals. Both pinned
proofs must pass our verifier and the independent process (successful exit and
acceptance marker). Tiny also uses the independent H/MSM JSON vectors, malformed
key/CSR guards, witness length and constant-wire guards, H length boundaries,
and distinct valid witnesses on concurrent calls to one prepared circuit.
CPU query-shape rejection is checked at `msms`, where the CPU implementation
validates bases; GPU query-shape rejection is checked at `prepare`. CSR/header
rejection is checked at `prepare` for all backends.
SHA uses a CPU stage oracle and independent proof verification only; there is
no claim of an independent SHA stage oracle. Foreign device handles are not
assumed invalid across circuits beyond the API contract.

Reserve one physical GPU slot and run these commands serially, without benches.
Compile-only checks do not count as device execution:

```sh
cargo test --release --locked --offline -j 2 -p snarkrs-cli --features metal --test conformance --test large --no-run
cargo test --release --locked --offline -j 2 -p snarkrs-cli --no-default-features --features cpu,wgpu --test conformance --test large --no-run
cargo test --release --locked --offline -j 2 -p snarkrs-cli --no-default-features --features cpu,cuda --test conformance --test large --no-run
G16_CONFORMANCE_BACKEND=metal G16_CONFORMANCE_WORK=variable G16_CONFORMANCE_PROFILE=none cargo test --release --locked --offline -j 2 -p snarkrs-cli --features metal --test conformance required_backend_conformance -- --ignored --exact --nocapture --test-threads=1
G16_CONFORMANCE_BACKEND=metal G16_CONFORMANCE_WORK=constant G16_CONFORMANCE_PROFILE=none cargo test --release --locked --offline -j 2 -p snarkrs-cli --features metal --test conformance required_backend_conformance -- --ignored --exact --nocapture --test-threads=1
G16_WGPU_LIMITS=floor G16_CONFORMANCE_BACKEND=wgpu G16_CONFORMANCE_WORK=variable G16_CONFORMANCE_PROFILE=floor cargo test --release --locked --offline -j 2 -p snarkrs-cli --no-default-features --features cpu,wgpu --test conformance required_backend_conformance -- --ignored --exact --nocapture --test-threads=1
G16_WGPU_LIMITS=floor G16_CONFORMANCE_BACKEND=wgpu G16_CONFORMANCE_WORK=constant G16_CONFORMANCE_PROFILE=floor cargo test --release --locked --offline -j 2 -p snarkrs-cli --no-default-features --features cpu,wgpu --test conformance required_backend_conformance -- --ignored --exact --nocapture --test-threads=1
G16_WGPU_LIMITS=auto G16_CONFORMANCE_BACKEND=wgpu G16_CONFORMANCE_WORK=variable G16_CONFORMANCE_PROFILE=auto cargo test --release --locked --offline -j 2 -p snarkrs-cli --no-default-features --features cpu,wgpu --test conformance required_backend_conformance -- --ignored --exact --nocapture --test-threads=1
G16_WGPU_LIMITS=auto G16_CONFORMANCE_BACKEND=wgpu G16_CONFORMANCE_WORK=constant G16_CONFORMANCE_PROFILE=auto cargo test --release --locked --offline -j 2 -p snarkrs-cli --no-default-features --features cpu,wgpu --test conformance required_backend_conformance -- --ignored --exact --nocapture --test-threads=1
```

Auto logs requested/effective caps and fallback reason. Auto falling back to Floor,
capacity not exceeding Floor, and software/unknown adapters are `UNAVAILABLE`,
not Auto-capacity or physical-job passes. Run Auto only where the requested
capacity is actually granted. Metal logs its device name. CPU/CUDA factory
metadata is not physical worker attestation. CUDA variable work requires a
separately available physical NVIDIA slot; CUDA constant work is explicitly
rejected because held lane D has not landed. Do not launch NVIDIA/phone jobs
from this gate. Successful local Metal/WGPU runs do not finish hardware parity.

Every successful gate prints the revision, backend, device information, work,
profile, fixture, domain, results, and exact completed count (`2/2`). Retain the
full output and the tested diff if the revision is not yet committed. A missing
result is unavailable coverage, not a pass.

## Large proof success and capacity refusal

The `large` target requires exactly `large/js_384x384_d32`, domain `2^22`, its
key/witness/vkey/reference public signals, and the same tiny verifier preflight.
It uses one explicit selection and checks both verifiers, reference public
signals, and exact completion (`1/1`). CLI proof processes always receive
`--fallback false --self-verify false`. WGPU preflight logs/rejects software
adapters and Auto fallback; retain child CLI diagnostics separately, because
preflight is not attestation of the child's device.

Large runs need separate coordinator approval for memory/time safety. Do not
run automatically after the bounded gate. Once approved, an exact Floor command
is (other approved selections use the same backend/work/profile variables):

```sh
G16_LARGE_FIXTURES=large/js_384x384_d32 G16_WGPU_LIMITS=floor G16_CONFORMANCE_BACKEND=wgpu G16_CONFORMANCE_WORK=variable G16_CONFORMANCE_PROFILE=floor cargo test --release --locked --offline -j 2 -p snarkrs-cli --no-default-features --features cpu,wgpu --test large every_backend_proves_the_large_artifacts -- --ignored --exact --nocapture --test-threads=1
```

Expected capacity refusal is a separate outcome, never large proof success.
Reuse the existing bounded CPU capacity tests and Floor `2^23` refusal test:

```sh
cargo test --release --locked --offline -j 2 -p snarkrs-wgpu --lib table_capacity -- --nocapture
cargo test --release --locked --offline -j 2 -p snarkrs-wgpu --test ntt floor_rejects_2_23_tables_before_allocation -- --exact --nocapture --test-threads=1
```

The latter requires the GPU slot and checks the precise pre-allocation binding
limit error, not arbitrary OOM, timeout, panic, or device failure. Existing
`check_onion_ready.py` may preflight resources but is not proof-success evidence.
No fixture generation, network access, rentals, or new tooling are part of this gate.
